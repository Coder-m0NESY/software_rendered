# 第 5 步教程：只打印数字，先别画

> 这份文档是**教程**，教你自己动手写，不是改动记录。
> 目标：手写立方体 8 个顶点 → 乘 MVP → `printf` 出 8 行数字。
> **这一步的产出是数字，不是画面。** 画线是第 6 步的事。
>
> 当前 `src/main.cpp` 里已经有一份能跑的成品。你可以把它整个删掉重写，
> 也可以先读一遍再自己写一遍 —— 但**别只是复制粘贴**，第九节的自测会暴露有没有真懂。

---

## 一、这一步要交什么

验收标准就一条：**终端里出现 8 行数字，目测合理。**

「合理」是三个具体的检查项：

| # | 检查什么 | 期望 |
| :---: | :--- | :--- |
| 1 | `w` 分量 | 近的顶点小、远的顶点大（只有两个值） |
| 2 | NDC 的 x、y | 全都落在 `[-1, 1]` 以内 |
| 3 | 近大远小 | 近的顶点 NDC 数值比远的更大 |

具体要求见第九节。

---

## 二、为什么必须先看数字，不能直接画

因为**画错了你分不清是谁的锅**。

矩阵写错、顺序乘反、行主序列主序搞混、`w` 忘了除 —— 这四种错误在屏幕上看起来**是同一个样子**：一团乱麻。你盯着画面看不出该改哪一行。

但数字错了是一眼能看出来的。比如：

- `w` 全等于 1 → 说明投影矩阵没起作用，你乘的是个没写 `m[3][2]` 的矩阵
- NDC 的 x 是 `-300` 这种数量级 → 说明你拿裁剪坐标当 NDC 用了，漏了透视除法
- 近的顶点 `w` 比远的还小 → 说明视图矩阵的符号翻反了

这些都是「看数字三秒钟定位、看画面三小时定位不了」的问题。

所以这一步**故意不画**。先把数据链路打通、核对干净。

## 三、要动哪个文件

只动一个：[`src/main.cpp`](file:///d:/SDL_project/softbymyself/src/main.cpp)。

`CMakeLists.txt` 不用改 —— `main.cpp` 本来就在构建里。`math/` 那两个 `.cpp` 也已经加进去了，所以 `mat.hpp` / `vec.hpp` 写错会真的编译报错，不会再有「构建是绿的但代码是错的」那种假象。

### 必须保留 `#include <SDL.h>`

哪怕这一步一个 SDL 函数都不用，这个 include 也不能删。原因在 `CMakeLists.txt` 的链接顺序里：

```
mingw32 -> SDL2main -> SDL2
```

`SDL2main` 提供了一个 `WinMain`，它内部会去调用 `SDL_main`。而 `SDL.h` 里有个宏会把你的 `main` **改名**成 `SDL_main`，两者才对得上。

去掉这个 include，`main` 就叫 `main` 了，于是链接报错：

```
undefined reference to `SDL_main'
```

（编译能过，链接才炸 —— 这种错误第一次见会懵。）

### 控制台输出用英文

Windows 控制台按 ANSI 代码页解码，UTF-8 源码里的中文 `printf` 出来容易变成乱码。
所以**代码注释可以写中文，打印出来的标签一律用英文**。

## 四、把这一步拆成 4 件事

```
1. 定 8 个顶点          ← 立方体，模型空间
2. 造三个矩阵            ← M、V、P
3. 合成 MVP              ← 一次矩阵乘法
4. 循环 8 个顶点，算完打印
```

第 4 件事里，`Mat44 * Vec3` 已经由库提供了，你只要调用。所以真正要写的是「组装」，一行算式都没有。

---

## 五、8 个顶点

立方体边长取 **2**，中心放在原点。这样 8 个顶点的每个分量都只有 `±1` 两种取值 —— 数字好看，算错了也容易发现。

```cpp
// 立方体：边长 2、中心在原点，所以每个分量都是 ±1
// 这一步不涉及三角形和索引，8 个点的顺序随便定
const Vec3 vertices[8] = {
    Vec3(-1.0f, -1.0f, -1.0f),   // 0  ┐
    Vec3( 1.0f, -1.0f, -1.0f),   // 1  │ z = -1 的四个点：离相机更远
    Vec3( 1.0f,  1.0f, -1.0f),   // 2  │
    Vec3(-1.0f,  1.0f, -1.0f),   // 3  ┘
    Vec3(-1.0f, -1.0f,  1.0f),   // 4  ┐
    Vec3( 1.0f, -1.0f,  1.0f),   // 5  │ z = +1 的四个点：离相机更近
    Vec3( 1.0f,  1.0f,  1.0f),   // 6  │
    Vec3(-1.0f,  1.0f,  1.0f),   // 7  ┘
};
```

**为什么边长是 2 而不是 1**：用 ±1 能让「这个顶点在第几象限」一目了然。边长取 1 的话就是 ±0.5，全是小数，读数字的时候更费劲。

**为什么先不管顺序**：这一步只打印，不需要把点连成三角形。顺序真正重要是第 6 步（连棱）和第 7 步（连三角形）—— 到那时你会回来给这 8 个点定一个明确的编号规律。

## 六、三个矩阵

库已经把矩阵算法写好了，你要做的只是**选对参数**。三个工厂函数都在 `mat.hpp` 里。

### 6.1 M：模型矩阵

```cpp
const Mat44 model = Mat44::identity();
```

单位阵的意思是「**模型空间 = 世界空间**」—— 立方体就摆在原点，不转、不缩、不平移。

这一步用单位阵不是偷懒。它让你在验证时**少一个变量**：如果数字不对，那一定是 V 或 P 的锅，跟 M 无关。等数字全对了，再换成下面这个来确认 M 通路也是好的：

```cpp
const Mat44 model = Mat44::rotateY(0.5f);   // 弧度，约 28.6°
```

### 6.2 V：视图矩阵

```cpp
const Mat44 view = Mat44::lookAt(Vec3(0.0f, 0.0f, 3.0f),    // eye  相机在哪
                                 Vec3(0.0f, 0.0f, 0.0f),    // target 看向哪
                                 Vec3(0.0f, 1.0f, 0.0f));   // up   头顶朝哪
```

`lookAt` 的结果是：**把世界搬到「相机在原点、朝 −Z 看」的坐标系**。

相机放在 `(0, 0, 3)`，也就是从 +Z 方向往原点看。这样：
- 立方体在相机正前方 **3** 个单位处
- 顶点里 z = +1 的那四个（编号 4–7）**离相机近**，z = −1 的（0–3）**远**
- 上下左右都是正的：x 往右、y 往上

**eye 为什么不能随便放**：立方体半高是 1，如果相机贴到 `(0,0,1)` 就跑到立方体内部了，一半顶点落在相机背后，`w` 会变成负数 —— 而这一步**没有裁剪**，负数 `w` 除下去会让坐标翻号，数字会变得莫名其妙。第 5 步老老实实放 `(0,0,3)`。

### 6.3 P：投影矩阵

```cpp
constexpr float kPi = 3.14159265358979f;
const Mat44 projection = Mat44::perspective(kPi / 3.0f,     // fovY：60°，单位是弧度
                                            800.0f / 600.0f, // aspect：宽高比
                                            0.1f,            // near：近平面距离
                                            100.0f);         // far：远平面距离
```

四个参数：

| 参数 | 含义 | 这里为什么这么选 |
| :--- | :--- | :--- |
| `fovY` | 竖直方向的视野角 | 60° 是常见默认值。`kPi/3` 就是 60°，**单位是弧度不是角度** |
| `aspect` | 宽 / 高 | 用窗口的宽高比，不然画面会被拉伸。800×600 就是 4:3 |
| `near` | 近平面到相机的距离 | 不能取 0（会导致除零） |
| `far` | 远平面到相机的距离 | 要大于场景里最远的物体 |

**最大的坑是 `fovY` 的单位**。`Mat44::rotateX/Y/Z` 和 `perspective` 全都收弧度。写 `60.0f` 进去不会编译报错，但画面会完全不对 —— 60 弧度的正切值毫无意义。

**near 取 0.1 是有代价的**，第九节会看到。

## 七、合成 MVP

```cpp
const Mat44 mvp = projection * view * model;
```

写法是**从左往右**，但**作用顺序是从右往左**：

```
顶点 v  ──M──► 世界  ──V──► 相机空间  ──P──► 裁剪空间
```

所以先被 `model` 作用，最后被 `projection` 作用。写成 `model * view * projection` 就完全错了 —— 那相当于先把点投影了再平移。

把这三个先乘成一个矩阵（而不是对每个顶点乘三次）有个实际好处：**8 个顶点只做 1 次矩阵乘法合成，而不是 24 次**。物体顶点越多，这个合并越划算。真实渲染器就是这么做的。

### `Mat44 * Vec3` 隐含了什么

```cpp
const Vec4 clip = mvp * vertices[i];
```

`Mat44::operator*(const Vec3&)` 内部是 `(*this) * Vec4(p, 1.0f)` —— **自动补上 `w = 1`**。

这个 1 很关键：它是「平移能对顶点生效」的原因。如果补的是 `w = 0`（表示「方向」而不是「位置」），平移就不会作用在它身上。`Mat44::transformDirection()` 就是补 0 的那个版本，变换法线时用它。

## 八、打印

```cpp
std::printf("%-4s %-20s %-34s %s\n",
            "idx", "model (x,y,z)", "clip (x,y,z,w)", "ndc (x,y,z)");

for (int i = 0; i < 8; ++i) {
    const Vec3& p = vertices[i];

    // Mat44 * Vec3 隐含 w = 1
    const Vec4 clip = mvp * p;

    // 透视除法：真实管线里这一步在「裁剪」之后，
    // 这里顺手算出来只是为了让数字更好读
    const Vec4 ndc = clip.perspectiveDivide();

    std::printf("%-4d (%+.1f,%+.1f,%+.1f)   (%+.3f,%+.3f,%+.3f,%+.3f)   (%+.3f,%+.3f,%+.3f)\n",
                i,
                p.x, p.y, p.z,
                clip.x, clip.y, clip.z, clip.w,
                ndc.x, ndc.y, ndc.z);
}
```

三个小点：

- **同时打印裁剪坐标和 NDC**。只看其中一个，你没法判断透视除法有没有生效。
- `%+.3f` 里的 `+` 是**强制显示正负号**。这样正负号能对齐成一列，一眼看出哪个顶点的哪个分量翻了号。
- 需要 `#include <cstdio>`（用 `std::printf` 就不用管 C 和 C++ 的链接差异）。

## 九、怎么读这 8 行数字

跑起来应该看到这样（这里只列了两行，你的应该是 8 行）：

```
idx  model (x,y,z)        clip (x,y,z,w)                     ndc (x,y,z)
0    (-1.0,-1.0,-1.0)   (-1.299,-1.732,+3.808,+4.000)   (-0.325,-0.433,+0.952)
4    (-1.0,-1.0,+1.0)   (-1.299,-1.732,+1.804,+2.000)   (-0.650,-0.866,+0.902)
```

### 观察 1：`w` 只有两个值 —— 4.000 和 2.000

顶点 0–3（z = −1，远）的 `w` 是 **4.000**；顶点 4–7（z = +1，近）的 `w` 是 **2.000**。

原因：投影矩阵把 `w` 塞成了 **−z_view**。

| 顶点组 | 模型 z | 相机空间 z | w = −z_view |
| :---: | :---: | :---: | :---: |
| 0–3 | −1 | 3 − (−1) 反号 → −4 | **4** |
| 4–7 | +1 | −2 | **2** |

相机在 z = 3：顶点 z = −1 离它 4 个单位，z = +1 离它 2 个单位。**`w` 就是「离相机多远」**。

这也正是深度测试时「`w` 越大越远」的来历。

### 观察 2：NDC 全部落在 [-1, 1] 内

x 最大 `±0.650`，y 最大 `±0.866`。这一关过了，说明**投影矩阵和透视除法是对的**。

如果 x 出现 `±3.2` 这种超出 1 的值，说明投影矩阵的 `m[0][0]`（也就是 `f/aspect`）算错了。
如果 y 超出，查 `m[1][1]`。

### 观察 3：近大远小 —— 藏在 NDC 里的 2 倍关系

看 NDC 的 x 列。同样是 `x = ±1` 的顶点：

| | 模型 x | NDC x |
| :--- | :---: | :---: |
| 远处的（顶点 0、3） | ±1 | **±0.325** |
| 近处的（顶点 4、7） | ±1 | **±0.650** |

**世界坐标一模一样宽，投到屏幕上近的占了两倍。** 这个 2 倍正好等于 `w` 的比值（4 : 2）。

这就是「除以 w」产生的效果 —— 它才是「近大远小」的来源，投影矩阵本身不产生它。

y 列同理：远处 `±0.433`，近处 `±0.866`，也是 2 倍。

### 观察 4：NDC 的 z 挤在 0.90 ~ 0.95（这不是 bug）

近处 `+0.902`，远处 `+0.952`，中间只差 0.05。

原因：**深度的分布是非线性的**（按 `1/z`），而且这里 `near = 0.1` 设得特别小。于是整个立方体（离相机 2~4）在深度上全被挤到了接近远平面的一端。

有两件事值得顺手验证：

- 「近处的精度比远处高」就是说这个：靠近平面的那一小段距离，分走了绝大部分深度取值范围。
- 这也是为什么 `near` 的值**不能乱设小**。取 0.1 意味着你把一半以上的深度精度浪费在了相机前方 0.1 到 1 之间的空间里，而那里什么都没有。

### 参考：完整的 8 行

```
idx  model (x,y,z)        clip (x,y,z,w)                     ndc (x,y,z)
0    (-1.0,-1.0,-1.0)   (-1.299,-1.732,+3.808,+4.000)   (-0.325,-0.433,+0.952)
1    (+1.0,-1.0,-1.0)   (+1.299,-1.732,+3.808,+4.000)   (+0.325,-0.433,+0.952)
2    (+1.0,+1.0,-1.0)   (+1.299,+1.732,+3.808,+4.000)   (+0.325,+0.433,+0.952)
3    (-1.0,+1.0,-1.0)   (-1.299,+1.732,+3.808,+4.000)   (-0.325,+0.433,+0.952)
4    (-1.0,-1.0,+1.0)   (-1.299,-1.732,+1.804,+2.000)   (-0.650,-0.866,+0.902)
5    (+1.0,-1.0,+1.0)   (+1.299,-1.732,+1.804,+2.000)   (+0.650,-0.866,+0.902)
6    (+1.0,+1.0,+1.0)   (+1.299,+1.732,+1.804,+2.000)   (+0.650,+0.866,+0.902)
7    (-1.0,+1.0,+1.0)   (-1.299,+1.732,+1.804,+2.000)   (-0.650,+0.866,+0.902)
```

自己写的版本只要**在这几个数量级上对得上**就算合格，小数点后第三位有微小差异无所谓。

## 十、三个自测实验

数字对了不等于懂了。做这三个实验，每个都会让你对某一块的认识从「知道」变成「确信」。

### 实验 1：把 M 换成旋转

```cpp
const Mat44 model = Mat44::rotateY(0.5f);
```

**预期**：8 个顶点的 `x`、`z` 全都变了，**`w` 也跟着变了**。

`w` 变是因为旋转改变了顶点到相机的距离。**如果 `w` 一点都不变，说明 M 根本没被用上**（比如你写成了 `projection * view`，把 model 漏了）。

这一步同时验证了「矩阵合并」是正确的：M 确实在 P·V·M 的最右边、最先作用。

### 实验 2：把相机挪开

```cpp
const Mat44 view = Mat44::lookAt(Vec3(3.0f, 0.0f, 3.0f), ...);   // eye 从 (0,0,3) 改成 (3,0,3)
```

**预期**：

- 所有 `w` 都变大了（相机退远了，每个顶点都更远）
- NDC 的 x 不再是「左右对称」的（相机在侧面看，立方体在视野里偏到一边）

**如果 NDC 的 x 仍然是对称的 ±0.325 / ±0.650，说明你的 `view` 没起作用。**

### 实验 3：把 near 从 0.1 改成 1.0

**预期**：NDC 的 z 从「挤成一团」变成明显拉开（近的可能变成 0.7 左右，远的接近 1.0）。

这个实验是**深度精度**的第一课。以后做深度测试时如果发现「远处的面互相闪烁」，回来看看 `near` 是不是设得太小。

## 十一、常见坑

### 1. 链接报 `undefined reference to 'SDL_main'`

`main.cpp` 里的 `#include <SDL.h>` 被删了。加回去。

### 2. 编译报 `undefined reference to 'operator*(Mat44 const&, Vec4 const&)'`

`mat.cpp` 没在构建里。检查 `CMakeLists.txt` 的 `add_executable` 里有没有 `src/math/mat.cpp` 和 `src/math/vec.cpp`。

### 3. 输出的中文是乱码

打印用的字面量写中文了。把标签改成英文（注释保持中文没关系）。

### 4. `w` 全是 1.000

投影矩阵没起作用。可能的原因：

- 忘记乘 `projection`（只写了 `view * model`）
- 乘法顺序写反了（写成 `model * view * projection`）

### 5. NDC 的数值是几百这个量级

拿裁剪坐标当 NDC 用了。检查有没有调 `perspectiveDivide()`。

### 6. 上下颠倒

第 5 步只是打印，看不出颠倒 —— 这个坑要到第 6 步做视口变换时才出现，先记着。

### 7. `perspective` 的第一个参数写了 `60.0f`

单位是弧度。60 弧度会让 `tan(fovY/2)` 是个完全无意义的数，NDC 会乱七八糟。写 `kPi / 3.0f`。
