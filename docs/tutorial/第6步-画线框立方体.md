# 第 6 步教程：画线框立方体

> 目标：屏幕窗口里出现一个旋转的立方体线框（12 条棱）。
>
> 前置：第 5 步做完 —— 8 个顶点乘完 MVP 后 `printf` 出来，数字目测合理。

---

## 一、一帧里干什么

```
开窗、建画布                     ← 只做一次，不进循环
┌─ 循环 ────────────────────────────────────────┐
│ 1. poll_events()  处理事件（关窗、Esc）           │
│ 2. clear()         清画布                        │
│ 3. 每帧重算 M（绕 Y 轴转一点）                   │
│ 4. draw_wireframe()  一次性把 12 条棱画完         │
│ 5. present()       把画布贴上屏幕                 │
└───────────────────────────────────────────────┘
```

第 5 步停在第 4 步之前（只打印数字）。第 6 步真正新增的是 3、4、5，其中 5（present）已经被 `Window` 写好了。

所以你的工作量：**一个旋转矩阵 + 一张棱表 + 一个画线函数**。

## 三、视口变换：NDC → 屏幕像素

第 5 步算出来的是 NDC，范围 [-1, 1]。屏幕是 800×600 个像素。需要换算：

```
sx = (ndc.x + 1) * 0.5 * width
sy = (1 - ndc.y) * 0.5 * height
```

x 好理解：-1 映射到 0（最左），+1 映射到 800（最右）。

**y 为什么要 `1 - ndc.y`**：NDC 里 y 向上为正（+1 在顶上），屏幕像素 y 向下为正（0 在顶上）。方向反了，所以要先用 1 减一下把方向倒过来。忘了这一步画面上下颠倒。

这个函数放在 `renderer.cpp` 里，叫 `viewport()`。

## 四、12 条棱

立方体 8 个顶点，顶点编号：

| 编号 | 坐标 | 位置 |
| :---: | :--- | :--- |
| 0 | (−1, −1, −1) | 远面左下 |
| 1 | (+1, −1, −1) | 远面右下 |
| 2 | (+1, +1, −1) | 远面右上 |
| 3 | (−1, +1, −1) | 远面左上 |
| 4 | (−1, −1, +1) | 近面左下 |
| 5 | (+1, −1, +1) | 近面右下 |
| 6 | (+1, +1, +1) | 近面右上 |
| 7 | (−1, +1, +1) | 近面左上 |

规律：0~3 是 z=-1（远面），4~7 是 z=+1（近面）。

12 条棱分三组：

```cpp
const int edges[12][2] = {
    {0, 1}, {1, 2}, {2, 3}, {3, 0},   // 远面 4 条
    {4, 5}, {5, 6}, {6, 7}, {7, 4},   // 近面 4 条
    {0, 4}, {1, 5}, {2, 6}, {3, 7},   // 前后对应角连 4 条
};
```

每行两个数字是顶点编号，意思是「把这两个顶点连起来画一条线」。

## 五、Bresenham 画线

### 问题：为什么不能写 `y = kx + b`

从 x0 循环到 x1，每步算 `y = k*(x-x0) + y0` 然后画点。问题：
1. 斜率大于 1 时线会断（x 走 1 格，y 跳好几格，中间像素没画）
2. 每步都做浮点乘法，慢
3. 四舍五入误差累积，线会抖

### 思路：用误差决定什么时候拐一格

斜率在 0~1 之间时，x 每步走 1 格，y 走不走靠一个累积误差决定：误差攒够半格了 y 就走一步并扣掉一格。

### 整数版

把误差乘 2 倍避免浮点，判断条件也跟着变。最终代码用两个技巧覆盖所有方向：
- 取 dx、dy 的绝对值让「距离」永远为正，用 sx/sy 记真实走向
- 当 |dy| > |dx| 时主轴换成 y，公式结构不变，只是 x、y 对调

完整代码在 `rasterizer.cpp`，核心就是两个分支（主轴 x 或主轴 y），每个分支一个 for 循环 + 一个决策参数 D。

### 手算验证

画 `(0,0)→(5,2)`，理想直线 y=0.4x，四舍五入后 y 应该是 0,0,1,1,2,2。Bresenham 画出来：`(0,0)(1,0)(2,1)(3,1)(4,2)(5,2)`，完全吻合。

## 六、renderer.cpp：视口变换 + 画线循环

这个文件只有两个函数，讲清楚就完了。

### `viewport` 函数

```cpp
void renderer::viewport(float ndc_x, float ndc_y,
                        int width, int height,
                        int& out_sx, int& out_sy)
{
    out_sx = static_cast<int>((ndc_x + 1.0f) * 0.5f * static_cast<float>(width));
    out_sy = static_cast<int>((1.0f - ndc_y) * 0.5f * static_cast<float>(height));
}
```

就两行乘法，把 NDC 的 [-1,1] 映射到 [0,width] 和 [0,height]。y 用 `1-` 翻转方向。输入浮点 NDC，输出整数像素坐标。`int&` 是引用输出——调用方传两个 int 变量进来，函数往里写结果。

### `draw_wireframe` 函数

```cpp
void renderer::draw_wireframe(PixelBuffer& fb,
                              const Mat44& mvp,
                              const Vec3* vertices, int vertex_count,
                              const int (*edges)[2], int edge_count,
                              uint32_t color)
```

参数意思：
- `fb`：画布，要往上面画像素
- `mvp`：合成好的 P·V·M 矩阵
- `vertices` + `vertex_count`：顶点数组（8 个 Vec3）
- `edges` + `edge_count`：棱表（12 行，每行 2 个 int）
- `color`：线的颜色

函数体分两步：

**第一步：把 8 个顶点全部算成屏幕坐标，存起来**

```cpp
for (int i = 0; i < vertex_count; ++i) {
    const Vec4 clip = mvp * vertices[i];       // 乘 MVP
    if (clip.w < 1e-6f) {                       // w<=0 说明在相机背后
        visible[i] = false;
        continue;
    }
    const Vec4 ndc = clip.perspectiveDivide();  // 除 w
    viewport(ndc.x, ndc.y, fb.width(), fb.height(),
             screen_x[i], screen_y[i]);         // NDC → 像素
}
```

**为什么要先全部算好再画**：12 条棱每条用 2 个顶点，如果每条棱单独变换就要做 24 次矩阵乘法。先算好存起来、画的时候查表，只做 8 次。这个「顶点数组 + 索引数组」的结构就是 GPU 的 vertex buffer + index buffer。

**`w < 1e-6` 防什么**：投影矩阵把 w 塞成 `-z_view`。顶点在相机背后时 w 为负，÷w 之后 x、y 翻号，画出来的线横穿整个屏幕（鬼畜线）。相机离立方体 3 个单位，实际碰不到，但这个检查防止你改相机位置时画面突然爆炸。用 `1e-6` 而不是 `0` 是因为浮点没有真正的零。

**第二步：按棱表画 12 条线**

```cpp
for (int e = 0; e < edge_count; ++e) {
    const int a = edges[e][0];
    const int b = edges[e][1];
    if (!visible[a] || !visible[b]) continue;
    draw_line(fb, screen_x[a], screen_y[a], screen_x[b], screen_y[b], color);
}
```

`edges[e][0]` 和 `edges[e][1]` 是两个顶点编号，拿编号去 `screen_x[]`、`screen_y[]` 里查坐标，交给 `draw_line` 画。有一个端点不可见就整条跳过。

## 七、main.cpp：组装一切

```cpp
int main(int argc, char* argv[])
{
    // 1. 建窗口和画布
    Window window("SoftRenderer - wireframe cube", 800, 600);
    PixelBuffer buffer(800, 600);

    // 2. 立方体顶点和棱表（见第四节）
    const Vec3 vertices[8] = { ... };
    const int edges[12][2] = { ... };

    // 3. 相机和投影（不变，放循环外）
    const Mat44 view = Mat44::lookAt(...);
    const Mat44 projection = Mat44::perspective(...);

    // 4. 主循环
    while (!window.closed()) {
        window.poll_events();
        buffer.clear(Color(0, 0, 0));               // 清屏

        const float angle = SDL_GetTicks64() * 0.001f;  // 每帧转一点
        const Mat44 model = Mat44::rotateY(angle);
        const Mat44 mvp = projection * view * model;

        renderer::draw_wireframe(buffer, mvp,       // 画 12 条棱
                                 vertices, 8,
                                 edges, 12,
                                 Color(255, 255, 255).to_pixel());

        window.present(buffer.surface()->pixels);   // 贴上屏幕
    }
}
```

**`#include <SDL.h>` 不能删**：CMakeLists 链接了 SDL2main，它提供的 WinMain 会去找被宏改名后的 `SDL_main`，SDL.h 里那个宏把 main 改名成 SDL_main。删了 include 就对不上了，链接报 `undefined reference to SDL_main`。

**`SDL_GetTicks64() * 0.001`**：`GetTicks64` 返回毫秒，乘 0.001 变成秒，所以 1 秒转 1 弧度，大约 6 秒一圈。

**`present` 那行**：`buffer.surface()->pixels` 是 SDL_Surface 里的裸像素数组，转成 `const uint32_t*` 传给 `present`，后者把它拷进 GPU 纹理再贴上屏幕。

## 九、常见坑

| 现象 | 原因 |
| :--- | :--- |
| 纯黑屏 | 忘了调 `present()`，或画线和 present 顺序反了 |
| 画面上下颠倒 | `viewport` 里 y 写成了 `(ndc.y + 1)`，应该是 `(1 - ndc.y)` |
| 8 个点全挤在左上角一小块 | 没做视口变换，直接拿 NDC 当像素坐标 |
| 线是断的 | Bresenham 写错了，斜率大于 1 时没走 y 分支 |
| 横穿全屏的乱线 | 相机背后有顶点（w≤0），÷w 后坐标翻号。检查 `w < 1e-6` 那行写了没 |
| `undefined reference to draw_line` | rasterizer.cpp 没加进 CMakeLists |

## 十、分三次验收

### 第一关：画 8 个点

把 `draw_wireframe` 里画线的部分暂时改成只画顶点：

```cpp
for (int i = 0; i < vertex_count; ++i) {
    if (visible[i]) fb.put_pixel(screen_x[i], screen_y[i], color);
}
```

期望：8 个白点，近面 4 个点围的四边形更大，远面 4 个点包在里面。这一关过了说明投影和视口变换都对。

### 第二关：连 12 条棱

换回 `draw_line`。期望：一个立方体线框。

### 第三关：让它转

把 M 从 `identity()` 换成 `rotateY(angle)`，angle 随时间增加。期望：线框转起来，棱始终连在正确的角上。
