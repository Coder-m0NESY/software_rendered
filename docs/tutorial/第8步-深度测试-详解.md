# 第 8 步：深度测试 —— 逐行详解

> 目标：给实心立方体加上深度测试，让「谁离相机近就画谁」，解决穿模问题。

---

## 一、现在的 bug 是什么

第 7 步画出的实心立方体，转动时会看到「后面的面盖住前面的面」。原因：12 个三角形按固定顺序画，后画的覆盖先画的，和远近无关。

## 二、解决思路：给每个像素存一个深度

```cpp
// 画新像素前，先和已存的比一比
if (新深度 < 旧深度) {
    覆盖颜色 + 更新深度
} else {
    跳过这个像素
}
```

这样无论画三角形的顺序如何，最终留在屏幕上的永远是离相机最近的片元。

## 三、深度从哪来：第 4 步的遗产

`PixelBuffer` 里已经有：

```cpp
std::vector<float> depth_;          // 和颜色缓冲同尺寸
float depth_at(int x, int y) const; // 读深度，越界返回 +1
void set_depth(int x, int y, float depth);  // 写深度
void clear_depth();                 // 整块刷成 +1
```

`clear()` 里已经顺带调了 `clear_depth()`——每帧开头深度全部重置成「什么都没画」。

**为什么清屏值是 +1？** 因为 NDC 的 z 是「越小越近」，-1 是近平面（最近），+1 是远平面（最远）。「什么都没有」必须是最远，这样任何真实深度都能赢过它。

## 四、存什么值当深度：clip.z vs ndc.z

这是最容易搞错的地方。两个选择：

| 候选 | 是什么 | 能不能直接插值 |
| :--- | :--- | :--- |
| `clip.z` | 透视除法**之前**的 z | **能**（线性） |
| `ndc.z` | `clip.z / w` | **不能**（非线性） |

**为什么 clip.z 是线性的？** 投影矩阵的设计就是让 `z_ndc = (Az + B) / (-z_view)`，所以 `clip.z = Az + B` 是 z 的线性函数。在三角形内部做线性插值，结果和「在 3D 空间插值再投影」一致。

**为什么 ndc.z 不行？** 除法让 z 变成非线性的。屏幕上等距的两个像素，它们的 ndc.z 差值不相等——近处变化快，远处变化慢。直接插值 ndc.z 会在三角形边缘产生错误的深度。

**为什么不用 z/w？** 学习路线第 314 行说「存 1/z 而不是 z」，那是针对**透视校正插值**的——UV、法线这些属性在屏幕上不是线性变化的，要按 `1/z` 插值。但**深度本身**就是 z，它已经是「透视除法后的 z」，在屏幕上是线性的。直接插值 z 就是正确的深度。

「存 1/z」的说法容易误导，改成「别存**视空间**的 z」更准确——视空间 z 是非线性的，不能直接插值；clip.z（或 ndc.z，但 clip.z 更好）是线性的，可以直接插值。

## 五、三角形内部怎么算深度

三个顶点的深度是 `z0`、`z1`、`z2`（clip.z），三角形内部某个像素的深度用**重心坐标插值**：

```cpp
const int w0 = edge_cross(x0, y0, x1, y1, x, y);  // 边 V0→V1
const int w1 = edge_cross(x1, y1, x2, y2, x, y);  // 边 V1→V2
const int w2 = edge_cross(x2, y2, x0, y0, x, y);  // 边 V2→V0

const int sum = w0 + w1 + w2;          // = 2 × 三角形总面积
if (sum == 0) continue;                // 退化三角形，跳过

const float inv = 1.0f / static_cast<float>(sum);

// 重心坐标：λ0 = w1/sum, λ1 = w2/sum, λ2 = w0/sum
// （注意对应关系：w0 是边 V0→V1 的边函数，权重给 V2）
const float z = (w1 * z0 + w2 * z1 + w0 * z2) * inv;
```

**为什么 w1 对应 z0？** 因为 w1 是边 V1→V2 的边函数，它衡量的是「点 P 到边 V1V2 的距离」。P 越靠近 V0，这个距离越大，w1 越大。所以 w1 是 V0 的权重。

**为什么除以 sum？** w0+w1+w2 = 2×三角形面积，是个恒定值。除以它，w 就变成了 [0,1] 的重心坐标（三个权重和为 1）。

## 六、代码怎么改：三处

### 1. rasterizer：加带深度的 draw_triangle_depth

```cpp
void draw_triangle_depth(PixelBuffer& fb,
                         int x0, int y0, float z0,
                         int x1, int y1, float z1,
                         int x2, int y2, float z2,
                         uint32_t color)
{
    // 包围盒（和原来一样）
    const int min_x = std::max(0, std::min({x0, x1, x2}));
    const int min_y = std::max(0, std::min({y0, y1, y2}));
    const int max_x = std::min(fb.width()  - 1, std::max({x0, x1, x2}));
    const int max_y = std::min(fb.height() - 1, std::max({y0, y1, y2}));

    for (int y = min_y; y <= max_y; ++y) {
        for (int x = min_x; x <= max_x; ++x) {
            const int w0 = edge_cross(x0, y0, x1, y1, x, y);
            const int w1 = edge_cross(x1, y1, x2, y2, x, y);
            const int w2 = edge_cross(x2, y2, x0, y0, x, y);

            if ((w0 >= 0 && w1 >= 0 && w2 >= 0) ||
                (w0 <= 0 && w1 <= 0 && w2 <= 0)) {

                // 算深度（重心坐标插值）
                const int sum = w0 + w1 + w2;
                if (sum == 0) continue;

                const float inv = 1.0f / static_cast<float>(sum);
                const float z = (w1 * z0 + w2 * z1 + w0 * z2) * inv;

                // 深度测试：更近才覆盖
                if (z < fb.depth_at(x, y)) {
                    fb.put_pixel(x, y, color);
                    fb.set_depth(x, y, z);
                }
            }
        }
    }
}
```

**为什么保留旧 draw_triangle 加新函数？** 旧函数的参数是 `(x, y)` 六个 int，新函数是 `(x, y, z)` 六个 int + 三个 float。C++ 不允许「参数个数相同但类型不同」的重载（会歧义），所以必须换名字。

### 2. renderer：把深度传过来

`draw_filled` 的第一个循环里，存 `clip.z`：

```cpp
float screen_z[kMaxVertices];   // 新增
...
const Vec4 clip = mvp * vertices[i];
if (clip.w < 1e-6f) { visible[i] = false; continue; }
visible[i] = true;
const Vec4 ndc = clip.perspectiveDivide();
viewport(ndc.x, ndc.y, fb.width(), fb.height(),
         screen_x[i], screen_y[i]);
screen_z[i] = clip.z;           // 存 clip.z，不是 ndc.z
```

第二个循环调 `draw_triangle_depth`：

```cpp
draw_triangle_depth(fb,
                    screen_x[a], screen_y[a], screen_z[a],
                    screen_x[b], screen_y[b], screen_z[b],
                    screen_x[c], screen_y[c], screen_z[c],
                    color);
```

### 3. main：clear 换成 clear_with_depth

```cpp
// 原来是 buffer.clear(Color(20, 20, 20));
// 改成：
buffer.clear_with_depth(Color(20, 20, 20));
```

`clear_with_depth` 是 `clear()` 的加强版：清颜色 + 清深度。`clear()` 里其实也会清深度（第 4 步加的），但 `clear_with_depth` 更明确，防止以后有人改 `clear()` 忘记同步。

## 八、常见坑

| 现象 | 原因 | 排查 |
| :--- | :--- | :--- |
| 还是穿模 | 比较方向写反了（`>` 写成 `<`） | NDC z 是**越小越近**，比较用 `<` |
| 全黑 | 深度初始值不是 +1 | `clear_depth()` 里刷的是 `kDepthFar = 1.0f` |
| 只有一半面显示 | 三角形绕序不统一 | 和深度无关，是第 7 步的坑 |
| 画面闪烁 | 忘了每帧清深度 | 确认调的是 `clear_with_depth` 不是 `SDL_FillRect` |

## 九、为什么 depth_at 越界返回 +1 不是 0

返回 0 的话，在 NDC 里是「正中间」。一个越界的像素（x < 0 或 x >= width）去读深度，拿到 0，比一半的真实片元都近——它就能通过深度测试，在画布外「画」出东西。虽然 `put_pixel` 会丢掉越界像素，但 `set_depth` 也会跟着写，污染深度缓冲。

返回 +1（最远），任何真实深度都赢不了它，越界像素永远被跳过。
