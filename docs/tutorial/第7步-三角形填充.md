# 第 7 步教程：三角形填充

> 目标：立方体从线框变成实心。转起来能看到 6 个面，不是 12 条空线。
>
> 前置：第 6 步做完——线框立方体能正常旋转。
>
> 验收：立方体变实心，转起来能看到面（后面的面盖住前面的面是正常的，第 8 步治）。

---

## 一、第 7 步干什么

第 6 步用 `draw_line` 画了 12 条棱。第 7 步换成 `fill_triangle`——把 12 个三角形（立方体 6 个面，每个面 2 个三角形）填满像素。

**一个面为什么是 2 个三角形**：光栅化器只会填三角形，矩形面要拆成两个三角形才能填。比如立方体的远面（顶点 0,1,2,3）拆成 `(0,1,2)` 和 `(0,2,3)`：

```
3 ------- 2
|       / |
|     /   |
|   /     |
| /       |
0 ------- 1

三角形 A: 0-1-2（左下半）
三角形 B: 0-2-3（右上半）
```

12 条棱 → 12 个三角形（6 个面 × 2 个三角形/面）。

## 二、算法：边函数 + 包围盒

### 为什么不用扫描线

扫描线光栅化是经典方法，但代码量大（要维护边表、活性边表、排序交点）。对于学习，**包围盒 + 逐像素边函数**最直观。

### 边函数是什么

三角形有三条边。边函数就是一个公式，告诉你「一个点在一条边的哪一侧」：

```
E(x, y) = (x - x0) * (y1 - y0) - (y - y0) * (x1 - x0)
```

`(x0,y0)` 和 `(x1,y1)` 是这条边的两个端点。`(x,y)` 是要测试的像素。

- E > 0：点在边的一侧
- E < 0：点在另一侧
- E = 0：点在边上

**一个像素在三角形内部，当且仅当它对三条边的边函数同号**（全正或全负，取决于顶点绕序）。

### 和有向面积的关系

三条边的边函数加起来，就是三角形的**有向面积**的 2 倍。如果面积为 0 或负数（顶点共线或绕序反了），三角形不可见，直接跳过。

这正是背面剔除用的同一个公式（学习路线 3.3 节）。

### 重心坐标

边函数还有一个妙用：三个边函数归一化后**就是重心坐标**。重心坐标能用来插值顶点属性（颜色、法线、UV）。第 9 步光照和第 10 步纹理都要用它。现在第 7 步只需要判断「在不在三角形里」，还用不到插值，但知道边函数能干这个，以后省事。

### 包围盒优化

对屏幕上每个像素都算边函数太慢（800×600 = 48 万次）。先算三角形的包围盒（三个顶点的 min/max x/y），只遍历包围盒内的像素。

## 三、思路：一步一步来

```
输入：三个屏幕坐标顶点 v0, v1, v2 + 颜色
  │
  │ 1. 算包围盒（min_x, max_x, min_y, max_y）
  │    裁到画布范围内（防止越界）
  ▼
  │ 2. 算三角形面积，面积 ≤ 0 就跳过（退化三角形/背面）
  ▼
  │ 3. 遍历包围盒每个像素：
  │    算三条边的边函数
  │    三个同号 → 像素在三角形内 → put_pixel
  ▼
输出：三角形填满了
```

## 五、三角形表

立方体 6 个面，每面 2 个三角形，共 12 个。顶点编号和第 6 步一样：

```cpp
const int triangles[12][3] = {
    // 远面 z=-1（顶点 0,1,2,3）
    {0, 1, 2}, {0, 2, 3},
    // 近面 z=+1（顶点 4,5,6,7）
    {4, 6, 5}, {4, 7, 6},
    // 底面 y=-1（顶点 0,1,4,5）
    {0, 1, 5}, {0, 5, 4},
    // 顶面 y=+1（顶点 2,3,6,7）
    {2, 6, 7}, {2, 7, 3},
    // 左面 x=-1（顶点 0,3,4,7）
    {0, 4, 7}, {0, 7, 3},
    // 右面 x=+1（顶点 1,2,5,6）
    {1, 2, 6}, {1, 6, 5},
};
```

**绕序很关键**：三个顶点的顺序决定了三角形朝哪边。绕序一致（全部顺时针或全部逆时针，从外面看）才能让背面剔除正常工作。上面这张表的绕序是从立方体**外面**看是逆时针的——如果你发现面全被剔了（立方体看不见），把每行的后两个数交换一下就行。

## 六、fill_triangle 的代码骨架

```cpp
void fill_triangle(PixelBuffer& fb,
                   int x0, int y0, int x1, int y1, int x2, int y2,
                   uint32_t color)
{
    // 1. 包围盒
    int min_x = std::min({x0, x1, x2});
    int max_x = std::max({x0, x1, x2});
    int min_y = std::min({y0, y1, y2});
    int max_y = std::max({y0, y1, y2});

    // 裁到画布内
    min_x = std::max(min_x, 0);
    min_y = std::max(min_y, 0);
    max_x = std::min(max_x, fb.width()  - 1);
    max_y = std::min(max_y, fb.height() - 1);

    // 2. 有向面积（也是边函数的基准）
    //    面积 ≤ 0 说明是退化三角形或背面，跳过
    float area = static_cast<float>((x1 - x0) * (y2 - y0) - (x2 - x0) * (y1 - y0));
    if (area == 0.0f) return;   // 三个点共线
    // 注意：area 的正负取决于绕序，这里先不剔除背面，
    //       因为你可能还没确定绕序对不对——先看到三角形再说

    // 3. 逐像素判断
    for (int py = min_y; py <= max_y; ++py) {
        for (int px = min_x; px <= max_x; ++px) {
            float w0 = edge_function(x1, y1, x2, y2, px, py);
            float w1 = edge_function(x2, y2, x0, y0, px, py);
            float w2 = edge_function(x0, y0, x1, y1, px, py);

            // 三个同号 = 在三角形内
            if ((w0 >= 0 && w1 >= 0 && w2 >= 0) ||
                (w0 <= 0 && w1 <= 0 && w2 <= 0)) {
                fb.put_pixel(px, py, color);
            }
        }
    }
}
```

`edge_function` 就一行：

```cpp
static float edge_function(int x0, int y0, int x1, int y1, int px, int py)
{
    return static_cast<float>((px - x0) * (y1 - y0) - (py - y0) * (x1 - x0));
}
```

## 七、renderer.cpp 怎么改

把 `draw_wireframe` 复制一份改成 `draw_filled`，区别只有两点：
1. 棱表 `edges[12][2]` 换成三角形表 `triangles[12][3]`
2. 第二个循环里调 `fill_triangle` 代替 `draw_line`

顶点变换循环（第一个循环）完全不用改——还是 8 个顶点乘 MVP 算屏幕坐标。变的只是第二个循环：从「12 条棱各画一条线」变成「12 个三角形各填一片像素」。

## 九、分三次验收

### 第一关：画一个测试三角形

先不连立方体。在屏幕中间硬画一个大三角形：

```cpp
fill_triangle(buffer, 200, 200, 600, 200, 400, 500, Color(255, 0, 0).to_pixel());
```

期望：屏幕中间一个红色实心三角形。这一步过了说明 `fill_triangle` 本身没问题。

### 第二关：立方体变实心

换上 `draw_filled` + 三角形表。期望：一个灰色实心立方体在转。

### 第三关：观察穿模

转的时候你会发现**后面的面有时候盖住前面的面**——这是正常的。因为没有深度测试，谁后画谁覆盖。第 8 步加上深度测试就正常了。

如果你看不到任何面（全黑），先检查绕序：把某个三角形的后两个顶点交换（`{0,1,2}` 改成 `{0,2,1}`），看是否出现。如果翻转后出现了，说明全部三角形的绕序要统一调整。

## 十、常见坑

| 现象 | 原因 |
| :--- | :--- |
| 三角形只画了轮廓没填满 | 边函数的 `>= 0` / `<= 0` 写成了 `> 0` / `< 0`，边界像素丢了 |
| 立方体全是黑的 | 三角形绕序反了，面积全为负，被 `area <= 0` 跳过。要么翻转绕序，要么先去掉面积检查 |
| 画面有闪烁的横线 | 某些三角形退化（三个点共线），area=0 导致除零或边界判断异常 |
| 性能很差 | 包围盒没裁到画布内，或者没算包围盒直接遍历全屏 |
| 立方体看起来「翻转」| 后面盖住了前面，正常现象，第 8 步治 |
