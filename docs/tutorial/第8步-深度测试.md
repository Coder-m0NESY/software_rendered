# 第 8 步：深度测试

> 第 7 步立方体变实心了，但转动时**后面的面会盖住前面的面**——谁后画谁覆盖，和远近无关。这就是穿模。这一步加上深度测试，让「谁离相机近就画谁」。

---

## 一、现在的 bug 是什么样

立方体绕 Y 轴转，当它转到「背面朝你」的时候，你会看到：
- 本该被正面挡住的背面，画出来了
- 正面的三角形反而被盖住了

原因：现在的 `draw_triangle` 只判断「这个像素在不在三角形里」，不判断「这个像素是不是离相机最近的那个」。所以后画的三角形无条件覆盖先画的。

## 二、解决思路：每个像素存一个深度

给每个像素配一个「离相机多远」的值。画新像素前，先和已存的比一比：

```
如果 新深度 < 旧深度：   覆盖颜色 + 更新深度
否则：                    跳过这个像素
```

这样无论画三角形的顺序如何，最终留在屏幕上的永远是离相机最近的片元。

## 三、深度从哪来

第 4 步已经在 `PixelBuffer` 里加了 `std::vector<float> depth_`，还有三个接口：

```cpp
float depth_at(int x, int y) const;   // 读某像素的深度，越界返回 +1（最远）
void set_depth(int x, int y, float depth);  // 写某像素的深度
void clear_depth();                   // 整块刷成 +1（最远）
```

`clear()` 里已经顺带调了 `clear_depth()`——每帧开头深度全部重置成「什么都没画」。

**存什么值当深度？** 存 NDC 的 z。`perspectiveDivide()` 之后 `z_ndc` 在 [-1, 1] 之间，-1 是近平面（最近），+1 是远平面（最远）。**z 越小越近**，所以比较时用 `<`。

**为什么不用 clip 的 w？** w 是「顶点到相机的距离」，但同一个像素可能被多个三角形覆盖，每个三角形的 w 不同。NDC z 是归一化后的深度，所有三角形在同一个坐标系下可比。

## 四、三角形内部怎么算深度

三个顶点的深度是 `z0`、`z1`、`z2`（NDC 值），三角形内部某个像素的深度用**重心坐标插值**：

```cpp
// w0、w1、w2 是边函数算出的三个值（= 2 倍子面积）
const int sum = w0 + w1 + w2;          // = 2 × 三角形总面积
const float inv = 1.0f / sum;

// 重心坐标：λ0 = w1/sum, λ1 = w2/sum, λ2 = w0/sum
// （注意对应关系：w0 是边 V0→V1 的边函数，权重给 V2）
const float z = (w1 * z0 + w2 * z1 + w0 * z2) * inv;
```

这样每个像素的深度都是三个顶点深度的加权平均，近处权重大、远处权重小，自然过渡。

## 五、代码怎么改

### 1. `draw_triangle` 加深度参数

现在的签名：

```cpp
void draw_triangle(PixelBuffer& fb,
                   int x0, int y0, int x1, int y1, int x2, int y2,
                   uint32_t color);
```

改成：

```cpp
void draw_triangle(PixelBuffer& fb,
                   int x0, int y0, float z0,
                   int x1, int y1, float z1,
                   int x2, int y2, float z2,
                   uint32_t color);
```

每个顶点多带一个 `float z`。

### 2. 内部加深度比较

在 `if ((w0 >= 0 && w1 >= 0 && w2 >= 0) || ...)` 那个分支里，原来直接 `put_pixel`，现在改成：

```cpp
const int sum = w0 + w1 + w2;
if (sum == 0) continue;

const float inv = 1.0f / static_cast<float>(sum);
const float z = (w1 * z0 + w2 * z1 + w0 * z2) * inv;

if (z < fb.depth_at(x, y)) {     // 新像素更近
    fb.put_pixel(x, y, color);   // 覆盖颜色
    fb.set_depth(x, y, z);       // 更新深度
}
```

### 3. renderer 把深度传过来

`renderer.cpp` 的 `draw_filled` 里，第一个循环算出 `ndc.z` 后存进数组：

```cpp
float screen_z[kMaxVertices];   // 新增
...
const Vec4 ndc = clip.perspectiveDivide();
viewport(ndc.x, ndc.y, fb.width(), fb.height(),
         screen_x[i], screen_y[i]);
screen_z[i] = ndc.z;            // 存 NDC z
```

第二个循环调 `draw_triangle` 时多传 3 个参数：

```cpp
draw_triangle(fb,
              screen_x[a], screen_y[a], screen_z[a],
              screen_x[b], screen_y[b], screen_z[b],
              screen_x[c], screen_y[c], screen_z[c],
              color);
```

## 七、常见坑

| 现象 | 原因 | 排查 |
| :--- | :--- | :--- |
| 还是穿模 | 比较方向写反了（`>` 写成 `<`） | NDC z 是**越小越近**，比较用 `<` |
| 全黑 | 深度初始值不是 +1 | `clear_depth()` 里刷的是 `kDepthFar = 1.0f` |
| 只有一半面显示 | 三角形绕序不统一，有的正有的反 | 和深度无关，是第 7 步的坑，检查 `triangles` 表 |
| 画面闪烁 | 忘了每帧 `clear_depth()` | `clear()` 里已经调了，确认你调的是 `clear()` 不是 `SDL_FillRect` |

## 八、为什么深度是 `z/w` 而不是 `1/z`

学习路线第 314 行说「存 `1/z` 而不是 `z`」，那是针对**透视校正插值**的——UV、法线这些属性在屏幕上不是线性变化的，要按 `1/z` 插值。

但**深度本身**就是 NDC z，它已经是「透视除法后的 z」，在屏幕上是线性的。直接插值 NDC z 就是正确的深度。

「存 `1/z`」的说法容易误导，改成「别存**视空间**的 z」更准确——视空间 z 是非线性的，不能直接插值；NDC z 是线性的，可以直接插值。
